AI research system

Machine-scale

The record must be

  • Standardizeda common format that makes the work shareable with any person or agent
  • Verifiableevery result can be checked and traced to how it was made
  • Compoundingnew work builds directly on prior results

Capture research at machine scale, without requiring human review of every intermediate step

Research community

Human-scale

The record must support

  • Human understandingpeople need to understand enough to assess, use, and redirect the work
  • Human communicationinsights travel through talks, discussions and careful writeups
  • Human agencypeople own the questions, out of curiosity or for social good

Its record is bounded by human scale, and may not look so different from today’s papers

Our bet: invest in shared, durable building blocks designed around these boundary conditions.

Structure of an ASTRA project managed by an AI agent

one ASTRA project · one git repository

1 · Describe

ASTRA

prior_insights:
  gaussian_noise:
    claim: noise is Gaussian at this depth
decisions:
  noise_model:
    rationale: drives the error budget
    options:
      gaussian:
        insights: [gaussian_noise]
      heavy_tailed:
        excluded: true
outputs:
  - id: fit_results
    decisions: [noise_model]
    recipe:
      command: python fit.py {decisions.noise_model}

astra.yaml The analysis as structured data: insights, decisions, rationale, recipes, outputs, findings.

2 · Execute & record

Lightcone CLI

Code and artifact versioning Code and spec in git, data and results in git-annex: every output committed with a content-addressed run record.

Reusable environment A uv lockfile, optionally in a container image, hashed on every output; recipes run sandboxed.

Connection to compute From a laptop to Dask, Kubernetes or Slurm clusters, under the same run record.

lc An agentic CLI that any agent harness can drive. Every output it produces carries certified provenance: what ran, on which inputs, in which environment, under which sandbox.

Looking ahead

Open questions to work on together

What is the necessary and sufficient set of properties for a scientific record to be navigable and certifiable for agents, and digestible and understandable for people?

Formalization

How far should we formalize?

Enough structure for agents to navigate and check, without over-formalizing: leave room for science that does not fit a schema.

Verification

Beyond reproducibility, what should a standard certify?

Provenance is certified; robustness to analysis choices, replication and review each need their own evidence.

Addressability

How do we make data and results universally addressable?

Which checkpoints to keep, and how another team finds and builds on them to continue or branch the work.

Adoption

What will make researchers adopt it?

Credit in hiring, funding and publication; which communities lead; a record easier to keep than to skip.
